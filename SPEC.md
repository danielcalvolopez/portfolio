# SPEC — Portfolio site for Dani Calvo

## Purpose

A portfolio for a frontend/full-stack engineer who builds complex SaaS platforms end to end. The site's job is to make one claim credible within 30 seconds: **"I own full products and features — from technical design to production — and I use AI (spec-driven + test-driven development) as engineering leverage, not a crutch."**

The site itself is exhibit A: fast, precise, obviously hand-crafted. It should feel like it was designed by an engineer with taste, not generated by a template or a model.

Audience: hiring managers and founders evaluating senior frontend/product engineers for platform work. Not design agencies, not awwwards judges.

## Non-goals

- No heavy scroll animation, no 3D, no awwwards theatrics.
- No blog (yet). No newsletter. No contact form (mailto/social links only).
- No CMS. Content lives in the repo as MDX/markdown. Editing content = a commit.

## Information architecture

1. **Home** — one screen of positioning + selected work. Name, one-line thesis, 2–3 featured case studies, link to "How I build". No generic hero fluff.
2. **Work** (`/work`) — index of case studies.
3. **Case study** (`/work/[slug]`) — the core content type. See template below.
4. **How I build** (`/process`) — spec-driven dev, TDD, AI workflow (Claude Code, subagent review passes, conformance suites), with one concrete worked example: spec → tests → production.
5. **About** (`/about`) — short. Background (incl. music production — it explains the taste and the systems thinking), stack, what I'm looking for. Links: GitHub, X (@danicalvo89), LinkedIn, email.

## Case study template (each ~600–1000 words)

- **Context** — what the product is, who it's for, my role (solo founder / engineer owning the feature).
- **Problem & constraints** — the actual engineering problem, not marketing copy.
- **Architecture & decisions** — 2–4 decisions with trade-offs stated honestly. Diagrams allowed (simple, static SVG).
- **What shipped** — screenshots or short clips, real metrics where available (perf numbers, recovery rates, load times).
- **What I'd do differently** — one honest paragraph. This section is non-negotiable; it's what separates a write-up from an ad.
- **Stack strip** — small, at the bottom, never the headline.

## Technical requirements

- Next.js (App Router), static export or fully static-rendered pages on Vercel. No client JS beyond what interaction strictly requires.
- Content as MDX with a typed frontmatter schema (title, slug, role, period, stack, summary, featured).
- Lighthouse 100/100/100/100 on every page, desktop and mobile. This is a hard requirement, and it gets stated on the site (small footer line: build hash + Lighthouse score + page weight).
- LCP < 1.0s on Fast 3G for the home page. Fonts self-hosted, subset, `font-display: optional` (measured 2026-07-22: `swap` puts the webfont repaint at 1.5s and becomes the LCP, failing the line above; `optional` keeps the size-adjusted fallback on slow first visits and guarantees zero CLS), zero CLS.
- OG images generated per page at build (satori + resvg pipeline, `scripts/og.mjs`).
- Accessible: keyboard navigable, visible focus states, `prefers-reduced-motion` respected, semantic HTML, AA contrast minimum.
- Analytics: none, or a single privacy-friendly pixel. Nothing that costs performance.

## Quality gates (TDD/spec-driven — this build demonstrates the workflow)

- Vitest: frontmatter schema validation, route generation, sitemap/OG correctness.
- Playwright: smoke nav on all routes, a11y checks (axe), visual regression on the 3 key pages.
- CI must pass Lighthouse budget assertions before deploy.
- Every feature branch: spec artifact first (`/specs/*.md`), then tests, then implementation, then subagent review pass. The `/process` page links to the real spec files of this very site.

## Definition of done (v1)

Home + all 3 case studies (RetryFi, Alkimi Labs, CrediLabs) + How I build + About, all quality gates green, deployed on custom domain, OG images verified in Slack/X/LinkedIn unfurls.
